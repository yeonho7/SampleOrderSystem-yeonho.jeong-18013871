# PRD — 반도체 시료 생산주문관리 시스템

## 1. 배경 및 목적

가상의 반도체 회사 **S-Semi**는 연구소, 팹리스(Fabless) 업체, 대학 연구실 등에 반도체 시료(Sample)를 납품한다.
주문량 급증으로 엑셀·메모장 기반 관리의 한계가 드러나면서 아래 문제가 반복되었다.

- 주문 처리 여부를 구두로 확인해야 하는 비효율
- 공정 완료 시점 파악 불가
- 충분한 재고가 있음에도 불필요한 생산 공정 가동

이 시스템은 **콘솔 기반 CLI 애플리케이션**으로, 담당자가 직접 명령을 입력하여 시료 등록부터 주문 접수·승인·생산·출고까지 전 과정을 통합 관리한다.

---

## 2. 사용자 및 역할

| 역할 | 설명 |
|------|------|
| **고객** | 시료 요청자. 필요한 시료를 이메일로 요청 |
| **주문 담당자** | 고객 요청을 받아 주문서를 작성·관리 |
| **생산 담당자** | 개발 시료를 등록하고, 주문 수신 후 승인 또는 거절 처리 |

흐름: 고객 시료 요청 → 주문 담당자 주문서 작성 → 생산 담당자 승인/거절

---

## 3. 주문 상태 흐름

```
RESERVED → [승인] → 재고 확인 → [재고 충분] → CONFIRMED → RELEASE
                            → [재고 부족] → PRODUCING → CONFIRMED → RELEASE
          → [거절] → REJECTED
```

| 상태 | 의미 |
|------|------|
| `RESERVED` | 주문 접수 |
| `REJECTED` | 주문 거절 (모니터링 제외) |
| `PRODUCING` | 주문 승인 완료, 재고 부족으로 생산 중 |
| `CONFIRMED` | 주문 승인 완료, 출고 대기 중 |
| `RELEASE` | 출고 완료 |

> `REJECTED`는 비정상 흐름으로 모니터링 집계에서 제외한다.

## 4. 기능 명세

### 4.1 메인 메뉴

시작 시 전체 시료 요약 정보를 표시하고 기능 선택 메뉴를 출력한다.

**요약 정보 표시 항목**
- 현재 시각
- 등록 시료 종 수, 총 재고 수량
- 전체 주문 건 수, 생산라인 대기 건 수

**메뉴 항목**

| 번호 | 메뉴 | 기능 |
|------|------|------|
| 1 | 시료 관리 | 시료 등록·조회·검색 |
| 2 | 시료 주문 | 고객 주문 접수 |
| 3 | 주문 승인/거절 | RESERVED 주문 처리 |
| 4 | 모니터링 | 주문량·재고 현황 조회 |
| 5 | 생산라인 조회 | 생산 현황·대기 큐 확인 |
| 6 | 출고 처리 | CONFIRMED 주문 출고 |
| 0 | 종료 | 프로그램 종료 |

---

### 4.2 시료 관리

시료(Sample)는 시스템의 기본 단위이며, 등록된 시료만 주문 가능하다.

#### 4.2.1 시료 등록

새로운 시료를 시스템에 추가한다.

**입력 항목**

| 필드 | 설명 |
|------|------|
| 시료 ID | 고유 식별자 (예: `S-001`) |
| 이름 | 시료명 (예: `실리콘 웨이퍼-8인치`) |
| 평균 생산시간 | 1개당 평균 생산 소요 시간 (단위: min/ea) |
| 수율 | 정상품 비율 = 정상 시료 수 / 총 생산 시료 수 (예: 0.92) |

#### 4.2.2 시료 목록 조회

등록된 모든 시료 목록을 출력한다. 각 항목에 현재 재고 수량도 함께 표시한다.

**표시 컬럼**: ID, 시료명, 평균 생산시간, 수율, 현재 재고

#### 4.2.3 시료 검색

이름 등 속성으로 특정 시료를 검색한다.

---

### 4.3 시료 주문 (접수)

고객 요청을 받아 주문을 생성한다. 생성된 주문의 초기 상태는 `RESERVED`이다.

**입력 항목**

| 필드 | 설명 |
|------|------|
| 시료 ID | 등록된 시료의 ID |
| 고객명 | 주문 고객 이름 |
| 주문 수량 | 요청 수량 (단위: ea) |

**처리 결과**: 주문번호(`ORD-YYYYMMDD-NNNN` 형식) 및 현재 상태(`RESERVED`) 출력

---

### 4.4 주문 승인/거절

`RESERVED` 상태의 주문 목록을 표시하고, 특정 주문을 승인 또는 거절한다.

#### 4.4.1 접수 주문 목록

`RESERVED` 상태의 주문만 표시한다.
**표시 컬럼**: 번호, 주문번호, 고객명, 시료명, 주문 수량, 상태

#### 4.4.2 주문 승인

승인 시 재고 상황에 따라 자동으로 두 가지 경로 중 하나로 처리된다.

| 조건 | 처리 |
|------|------|
| 재고 ≥ 주문 수량 | 즉시 `CONFIRMED` 상태로 전환 |
| 재고 < 주문 수량 | 생산라인에 자동 등록, 상태를 `PRODUCING`으로 전환 |

재고 부족 시 부족분 및 실 생산량, 예상 생산 시간을 화면에 안내한다.

#### 4.4.3 주문 거절

즉시 `REJECTED` 상태로 전환한다.

---

### 4.5 모니터링

담당자가 시스템 현황을 한눈에 파악할 수 있도록 두 가지 조회를 제공한다.

#### 4.5.1 주문량 확인

상태별 주문 건 수를 표시한다. (`REJECTED` 제외)

**표시 상태**: `RESERVED` / `CONFIRMED` / `PRODUCING` / `RELEASE`

#### 4.5.2 재고량 확인

시료별 현재 재고 수량과 재고 상태를 표시한다.

| 상태 | 조건 |
|------|------|
| 여유 | 주문 대비 재고 충분 |
| 부족 | 주문 대비 재고 수량 부족 |
| 고갈 | 재고 수량 = 0 |

---

### 4.6 생산라인

단일 생산 라인으로 운영되며, 주문이 들어온 시료에 대해서만 생산한다.

#### 4.6.1 생산량 계산

```
부족분      = 주문 수량 - 현재 재고
실 생산량   = ceil(부족분 / (수율 × 0.9))
총 생산시간 = 평균 생산시간 × 실 생산량
```

> 수율에 0.9를 곱하는 이유: 공정 오차를 고려한 안전 마진 확보

#### 4.6.2 생산 완료 처리

생산 완료 시 해당 주문 상태를 `PRODUCING` → `CONFIRMED`으로 자동 전환한다.

#### 4.6.3 생산 현황 표시

현재 생산 중인 시료의 정보를 표시한다.

**표시 항목 (예시)**: 주문번호, 시료명, 주문 수량, 현재 재고, 부족분, 실 생산량, 진행률, 완료 예정 시각

#### 4.6.4 대기 주문 확인

생산 큐에 대기 중인 주문 목록을 출력한다.

- **스케줄링 전략**: FIFO (선입선출)
- **표시 항목**: 순서, 주문번호, 시료명, 주문 수량, 부족분, 실 생산량, 예상 완료 시각

---

### 4.7 출고 처리

`CONFIRMED` 상태의 주문에 대해 출고를 실행한다.

**처리 결과**
- 주문 상태: `CONFIRMED` → `RELEASE`
- 출고 정보 출력: 주문번호, 출고 수량, 처리 일시, 상태 변경

## 5. 데이터 모델

### Sample (시료)

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | String | 고유 식별자 (예: `S-001`) |
| `name` | String | 시료명 |
| `avgProductionTime` | double | 평균 생산시간 (min/ea) |
| `yield` | double | 수율 (0.0 ~ 1.0) |
| `stock` | int | 현재 재고 수량 |

### Order (주문)

| 필드 | 타입 | 설명 |
|------|------|------|
| `orderId` | String | 주문번호 (`ORD-YYYYMMDD-NNNN`) |
| `sampleId` | String | 시료 ID (외래키) |

| `status` | Enum | `RESERVED` / `REJECTED` / `PRODUCING` / `CONFIRMED` / `RELEASE` |
| `createdAt` | DateTime | 주문 접수 일시 |
| `updatedAt` | DateTime | 상태 변경 일시 |

### ProductionJob (생산 작업)

| 필드 | 타입 | 설명 |
|------|------|------|
| `orderId` | String | 연결된 주문번호 |
| `sampleId` | String | 생산할 시료 ID |
| `shortage` | int | 부족분 수량 |
| `actualProduction` | int | 실 생산량 (`ceil(shortage / (yield × 0.9))`) |
| `totalTime` | double | 총 생산 예상 시간 (min) |
| `enqueuedAt` | DateTime | 큐 등록 일시 |

## 7. 제약 사항

- 생산 라인은 단일 라인이며 시료를 하나씩 순차 생산한다.
- 시스템에 등록되지 않은 시료는 주문 불가하다.
- `REJECTED` 주문은 모니터링 집계에서 제외한다.
- 출고(`RELEASE`) 처리는 `CONFIRMED` 상태의 주문에 대해서만 가능하다.

## 8. 주요 비즈니스 로직 요약

```
주문 승인 흐름:
  if 재고 >= 주문 수량:
      상태 → CONFIRMED
  else:
      부족분 = 주문 수량 - 재고
      실 생산량 = ceil(부족분 / (수율 × 0.9))
      생산 큐에 enqueue (FIFO)
      상태 → PRODUCING

생산 완료 시:
  재고 += 실 생산량 (수율 적용 후 정상품)
  상태 PRODUCING → CONFIRMED

출고 처리 시:
  재고 -= 주문 수량
  상태 CONFIRMED → RELEASE
```
